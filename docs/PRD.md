# AI Qt 原型生成器 PRD

## 1. 产品定义与目标用户

AI Qt 原型生成器是一款供个人在本地使用的 AI 原型工具。用户输入功能设计文档，产品通过 opencode 生成可直接操作的 PySide2 原型，并支持使用设计系统和基于批注继续迭代。

目标用户是需要快速验证页面结构、功能流程和基础交互的产品创建者。用户能够判断需求和原型效果，但不需要为每次评审手工编写 Qt 代码。

## 2. 功能需求

### FR-001 首次环境准备

用户首次打开产品时，系统自动准备并检查 OpenCode 和项目目录下的 Python/PySide2 虚拟环境。环境准备完成后，用户选择“无”或一份设计系统并进入工作台。

验收要求：

- 系统自动探测 OpenCode，并自动创建或使用项目目录下的 `.venv` 安装 PySide2，无需用户配置运行路径。
- 页面显示环境准备和检查状态；失败时显示简短原因并允许重试。
- 环境检查通过后，页面平铺展示“无”和设计系统库中的各个设计系统名称；用户完成选择后进入工作台，后续打开产品直接进入。

### FR-002 设计系统配置

用户可以选择“无”，完全由 Agent 决定 UI/UX，也可以从设计系统库中选择一份设计系统。设计系统库同时包含产品预置和用户导入的设计系统，所有设计系统均采用 SKILL 格式。

验收要求：

- 用户当前只能选择“无”或一份设计系统；选择“无”时，Agent 根据功能设计文档自行决定界面样式和交互方式。
- 产品可以预置多份设计系统，用户也可以通过 ZIP 导入更多设计系统。预置和导入项的格式、加载方式和生成行为相同，仅通过来源标签区分。
- 导入的 ZIP 根目录或唯一的顶层目录中包含 `SKILL.md`。
- `SKILL.md` 只要求包含 `name` 和 `description`；内部框架、UI 规范、组件库、示例及其他内容均为可选。
- 导入只将设计系统加入本地库，不自动设为当前选择；再次导入同名的用户导入项时，由用户确认是否更新。
- 用户可以删除未使用的导入项；当前使用项需要先切换后才能删除，产品预置项不可删除。
- 设置页和生成页输入区均平铺展示“无”及所有设计系统名称。选择立即保存并用于之后开始的生成任务；任务运行期间不可切换。

### FR-003 功能设计文档输入

用户可以粘贴文字，或上传 Markdown、TXT、DOCX 功能设计文档。系统从文档中提取文字作为原型生成需求。

验收要求：

- 系统能够读取并保留用户输入或上传的文档正文。
- 没有有效文字时，用户不能开始生成。
- 图片、截图和扫描内容不作为需求输入；文档有效文字不足时，页面提示用户补充文字。

### FR-004 原型生成与预览

用户通过一次操作调用 opencode。系统结合当前功能设计文档和所选设计系统生成 PySide2 原型，并自动补充产品评审所需的模拟数据和基础交互。缺少不影响主要页面或流程的信息时，系统采用常见默认值。

验收要求：

- 用户无需经过项目向导、规格确认或技术参数选择即可开始生成。
- 原型使用项目目录 `.venv` 中的 PySide2；选择设计系统时遵循该设计系统，选择“无”时由 Agent 自行设计 UI/UX。
- 文档明确描述的页面、表单、列表、弹窗和基础交互可以实际操作；外部能力以模拟数据或模拟反馈呈现。
- 原型成功启动后，页面直接显示可操作的原型预览；静态截图、不可操作界面或仅生成代码不视为成功。
- 生成失败时，页面保留功能设计文档，显示简短失败原因并允许重试。

### FR-005 原型批注

原型生成成功后，用户可以进入批注模式，在当前原型上添加位置化文字批注。系统为批注关联定位所需的页面、控件和位置上下文。

验收要求：

- 用户可以添加、定位、编辑和删除当前批注。
- 每条批注包含文字及对应的页面、控件和位置上下文。
- 用户可以从批注定位到原型中的对应位置。
- 批注模式下的点击用于创建或选择批注；退出批注模式后，原型恢复正常操作。

### FR-006 基于批注重新生成

用户可以一次提交当前全部有效批注。系统将功能设计文档、当前选择的设计系统（如有）、现有原型和批注内容交给 opencode，生成修改后的原型。

验收要求：

- 没有有效批注时，用户不能开始重新生成。
- 一次操作即可提交全部有效批注并开始重新生成。
- 处理期间页面显示正在生成，完成后明确显示成功或失败。
- 成功后，页面显示更新后的可操作原型，并清空已应用的批注。
- 失败时，页面保留原型和全部当前批注，并允许重试。
